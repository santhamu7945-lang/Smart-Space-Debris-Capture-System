02 / MISSION DOSSIER / ADCS-01

One mission, one traceable sequence.

The mission is written as a sequence of engineering states. Each stage has a purpose, an input, an expected output and a verification point. The result is a record that can be reviewed independently of the visual animation.

01OBSERVE
02ESTIMATE
03DECIDE
04ACT
05RE-OBSERVE
15 STAGES

Mission flow from search to reset.

This is a conceptual mission model. It uses standard spacecraft operations terminology while keeping the boundary between simulation, laboratory prototype and flight operation explicit.

01SURVEILLANCE

Establish the orbital picture

Identify the monitored region and collect the current object set.

INPUTCatalog/state records
OUTPUTSurveillance field
AUTHORITYTracking service
VERIFYCoverage and timestamp
02DETECTION

Find candidate debris

Separate object signatures that require continued monitoring.

INPUTPosition and motion observations
OUTPUTCandidate set
AUTHORITYDetection logic
VERIFYFalse-positive screening
03TRACKING

Maintain object identity

Associate observations over time so an object is not treated as new at every update.

INPUTCandidate observations
OUTPUTTrack record
AUTHORITYMulti-object tracker
VERIFYTrack continuity
04STATE ESTIMATION

Build a usable state

Produce position and velocity values in the defined orbital frame.

INPUTTrack history
OUTPUTState vector
AUTHORITYEstimator
VERIFYFrame and units
05RISK ASSESSMENT

Measure the operational concern

Evaluate separation, relative motion and mission constraints before approach.

INPUTTarget state
OUTPUTRisk record
AUTHORITYRisk model
VERIFYMargin and threshold
06TARGET SELECTION

Choose one active target

Select the object carried forward into the mission sequence.

INPUTCandidate risk records
OUTPUTTarget lock
AUTHORITYMission planner
VERIFYTarget identity
07DECISION

Authorize or hold

Apply the mission rule to the current target state and capture feasibility.

INPUTRisk + capture assessment
OUTPUTHOLD / PROCEED / ABORT
AUTHORITYDecision logic
VERIFYDecision trace
08REORIENTATION

Set the required pointing

Place the servicer in the attitude needed for the next navigation or capture operation.

INPUTTarget geometry
OUTPUTPointing state
AUTHORITYAttitude model
VERIFYKeep-out geometry
09RENDEZVOUS

Reduce relative separation

Plan a controlled transfer toward the target without confusing orbital coordinates with arm coordinates.

INPUTRelative state
OUTPUTRendezvous state
AUTHORITYGuidance model
VERIFYRelative motion
10CONTROLLED APPROACH

Enter the capture region

Reduce closing motion and maintain the defined approach envelope.

INPUTRelative position/velocity
OUTPUTApproach state
AUTHORITYApproach controller
VERIFYVelocity and distance limits
11CAPTURE CONFIGURATION

Prepare the mechanism

Select the appropriate arm or net configuration and verify readiness.

INPUTTarget geometry + mechanism status
OUTPUTCapture-ready state
AUTHORITYCapture manager
VERIFYMechanism clearance
12ROBOTIC CAPTURE

Secure the object

Execute the selected capture action and verify retention.

INPUTCapture-ready state
OUTPUTCaptured / abort
AUTHORITYCapture controller
VERIFYRetention check
13DEBRIS TRANSFER

Move the object to containment

Transfer the secured object through the defined local workspace.

INPUTCaptured object state
OUTPUTTransfer state
AUTHORITYArm controller
VERIFYWorkspace clearance
14STORAGE

Confirm containment

Place the object in storage and update the mass record.

INPUTTransfer state
OUTPUTStored state
AUTHORITYStorage manager
VERIFYPositive retention
15RESET

Return to monitoring

Close the current sequence and prepare for the next target.

INPUTStored / aborted state
OUTPUTSurveillance
AUTHORITYMission manager
VERIFYState reset
ENGINEERING RECORD

State changes should leave a reason behind.

STATE

What changed?

The mission state identifies where the sequence is and prevents an action from being treated as valid simply because a button was pressed.

DECISION

Why continue?

Risk, relative motion, mechanism readiness and available margin are evaluated before the sequence advances.

VERIFICATION

How is it checked?

Every stage has a verification focus so the interface can be reviewed against a defined engineering record.
